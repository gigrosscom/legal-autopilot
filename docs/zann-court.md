# Судебная практика для Zann: что открыто и как собираем

Решение владельца 01.10.2026: брать всё, что открыто и доступно: банк судебных актов, постановления и обзоры
Верховного Суда, открытые датасеты. Условия: собирать в щадящем темпе, хранить на нашем сервере в КЗ. Перед
обучением и любой передачей за рубеж (NVIDIA, Kaggle, Hugging Face) тексты автоматически обезличиваются.

Код: `apps/api/konsilier/zann/court.py` (сборщик), `apps/api/konsilier/zann/anonymize.py` (обезличивание) —
общие, без привязки к стране. Всё, что относится к Казахстану, — данные пакета: `packs/kz/zann/court.yaml`
(источники sud.kz/sud.gov.kz, шаблоны адресов, категории и ключевые слова, даты, языки) и
`packs/kz/zann/anonymize.yaml` (метки ИИН/БИН, формы юрлиц, слова адресов, форматы телефонов, госномеров,
счетов, документов, роли ru/kk). Таблицы — миграция `0027_zann_court`. Тесты — `tests/test_zann_court.py`, `tests/test_zann_anonymize.py`.

Условия использования sud.kz (https://sud.kz/rus/node/10088): материалы можно использовать с обязательной
гиперссылкой на sud.kz. Поэтому в манифесте у каждого документа есть `url`, и он сохраняется в выгрузке.

Сеть и User-Agent (проверено 01.10.2026 вечером, после суток без единого документа на сервере):
- sud.kz **молча рвёт соединение** («Server disconnected», ≈1 с), если в User-Agent есть слова `collector`,
  `spider`, `bot`, `httpx` — включая запрос robots.txt. Прежний User-Agent сборщика содержал «collector», поэтому
  robots.txt не читался ни разу, и каждый прогон останавливался на нём (на сервере — `pages=0/4 docs=0`). Дело не в
  стране: с машины вне КЗ те же страницы отдаются с другим User-Agent.
- Файловый сервис sud.gov.kz (JBoss, `/library/download/<id>`) отвечает **404** на User-Agent без «платформы»
  вида `(Windows NT 10.0; …)` — даже на `Mozilla/5.0 (compatible; …)`.
- **Это технические ограничения для роботов, мы их не обходим** (правило владельца: без маскировки и без обхода
  ограничений). Сборщик называет себя честно (`Konsilier.AI/1.0 (+https://konsilier.com; …)`, контакт — в `From`) и
  при таком отказе показывает `state=blocked(robots_unreachable)`. Под браузер не маскируемся.
- Законные пути к материалам ВС: (1) письмо в ВС с просьбой разрешить сбор открытых НП, обзоров и бюллетеней нашим
  роботом (или дать выгрузку); (2) Smart Bridge DODSVS-S-3457; (3) скачать файлы вручную (≈80 обзоров + бюллетени +
  НП) и загрузить командой `zann-court-import`. Нормативные постановления ВС уже собираются с adilet (тип НПВС).
- Изредка sud.kz рвёт и обычный запрос (через ≈12 с). Сборщик повторяет запрос с паузой 10 → 20 → 40 с. Если
  robots.txt так и не прочитан, прогон останавливается (`stopped=unreachable`, состояние
  `blocked(robots_unreachable)`), и задача пробует снова через 15 минут. 429 и Retry-After не встречали; если
  появятся — соблюдаются.

Разбор проверен на настоящих страницах 01.10: 148 листов дерева постановлений, 80 ссылок на обзоры, 14 лет
бюллетеней; DOCX постановления скачан и прочитан.

## 2. Банк судебных актов: как получить законно

- **Smart Bridge**, сервис «Доступ к открытым судебным актам» для LegalTech (sb.egov.kz, с 29.04.2022).
  Нужно юрлицо: ТОО ещё не зарегистрировано (`decisions.md`, 29.09). Черновик письма в ВС уже есть:
  `team/smart-bridge/07-supreme-court-letter.md`.
- **Письмо в Верховный Суд** с просьбой о выгрузке обезличенных актов по категориям для исследования.
- Пока доступа нет, юрист может сохранять отдельные акты вручную, через обычный интерфейс с капчей. Их
  загружает команда импорта (раздел 5): то же хранилище, манифест и обезличенная выгрузка, источник `acts`.

## 3. Как собираем (`konsilier/zann/court.py`)

- **Очередь в БД.** В `zann_court_pages` — страницы для обхода: индекс, затем листы. В `zann_court_docs` —
  документы со статусами pending → done / notext / missing / error, до 3 попыток. Прогон ограничен по времени,
  следующий продолжает с того же места.
- **Приоритет — наши сценарии.** Категория определяется по названию; если по названию не ясно — по началу
  текста. Порядок: потребители → труд → жильё и аренда → алименты и семья → административные штрафы
  (КоАП) → споры с госорганами (АППК) → кредиты и займы → прочее. Внутри категории: постановления, затем
  обзоры, затем бюллетени. Утратившие силу постановления идут в самом конце.
- **Темп.** Один запрос за раз, пауза `ZANN_COURT_PAUSE` (по умолчанию 1 с, не меньше 0,5 с). Поверх неё
  действует `Crawl-delay` из robots.txt: у sud.kz это 10 с, то есть фактически 1 запрос в 10 с. На 429 и 5xx —
  повтор с паузой (`Retry-After`, если сайт его прислал), на обрывы соединения — тоже. После 5 ошибок подряд
  прогон останавливается.
- **Хранение — только наш сервер** (адаптер хранилища, gzip):
  `zann/court/orig/<id>.<ext>.gz` — оригинал файла,
  `zann/court/text/<id>.txt.gz` — **уже обезличенный** текст (только он индексируется, ищется и идёт в обучение;
  необезличенный текст есть только внутри оригинала) (DOCX, PDF с текстовым слоем, RTF; у сканов и старых .doc текста нет,
  статус `notext`, оригинал хранится),
  `zann/court/manifest.jsonl.gz` — манифест: суд, категория, дата, номер, название, язык, статус, url,
  sha256, знаки, байты.
  Повторно файл не скачивается: документы известны по url. Раз в `ZANN_COURT_REFRESH_DAYS` страницы обходятся
  заново, чтобы найти новые документы.
- **Ход сбора** виден в `/v1/admin/metrics` (`zann_court`, с `status`) и в строке последовательной консоли
  (deploy/update.sh, раз в 15 минут, рядом со строкой `zann …`):
  `zanncourt state=… last_error='…' last_run=… next_run=… docs=… done=… notext=… pending=… error=… pages=done/всего …`.
  `state`: `running` (идёт прогон), `waiting` (прогон закончен, ждёт `next_run`), `blocked(robots_unreachable)`
  (robots.txt не прочитан), `blocked(robots_closed)` (robots.txt закрыл страницу), `no_sources` (нет пакета с
  `zann/court.yaml` или неизвестные `ZANN_COURT_SOURCES`), `error(<причина>)`, `never_run`, `disabled`. Состояние,
  последняя ошибка и время прогонов хранятся в строке `#status` таблицы `zann_court_pages` (без миграции).

## 4. Объём и время (оценка)

| Что | Сколько | Запросов | Время при 10 с на запрос |
|---|---|---|---|
| Дерево постановлений | 148 листов «группа/год» | ≈ 150 | ≈ 25 мин |
| Постановления (DOCX, ru + kk) | ≈ 250–350 постановлений → ≈ 500–700 файлов, ≈ 50–80 КБ каждый | ≈ 600 | ≈ 1,7 ч |
| Обзоры и обобщения | ≈ 80 ссылок ru + kk-страница | ≈ 100 | ≈ 20 мин |
| Бюллетени | 14 лет, по 1–5 PDF, 5–10 МБ каждый | ≈ 15 + 50 | ≈ 15 мин + загрузка (≈ 0,5 ГБ) |
| **Итого** | **≈ 750–950 документов, ≈ 0,6–0,8 ГБ оригиналов** | **≈ 1 000** | **≈ 3–4 ч** |

В тексте это примерно 60–120 млн знаков: бюллетени крупные, постановления — по 30–80 тыс. знаков. В ночном
режиме (50 минут за ночь) сбор займёт 4–5 ночей, в непрерывном (`ZANN_COURT_HOUR=-1`) — один вечер. Потом
сборщик раз в 30 дней обходит страницы и докачивает только новое.

## 5. Обезличивание и выгрузка (`konsilier/zann/anonymize.py`)

Перед обучением и перед любой передачей за рубеж используются только обезличенные тексты. Оригиналы с
сервера не уходят. Замена работает по правилам, без сети и без модели. Метки нумеруются внутри документа:
один и тот же человек или номер везде получает одну метку.

| Метка | Что заменяется |
|---|---|
| `[ФИО1]` | ФИО в ru/kk формах (в том числе отчества на -ұлы/-қызы); «Фамилия И.О.», «И.О. Фамилия»; роль + фамилия («истец Ахметов», «талапкер Нұрланов»); все падежные формы найденной фамилии (Ахметову, Ахметовқа, Ахметовтың) |
| `[ИИН1]` / `[БИН1]` | 12 цифр. БИН остаётся, только если это явно организация: стоит «БИН» и рядом форма юрлица (ТОО, АО, ГУ, ЖШС…). Если неясно — маскируется |
| `[АДРЕС1]` | улица, дом, квартира («ул. Абая, д. 10, кв. 5», «Абай көшесі, 15 үй, 3 пәтер», «мкр. Самал-2»). Город, район и суд остаются |
| `[ТЕЛ1]`, `[EMAIL1]` | телефоны, e-mail |
| `[ДОК1]` | номера удостоверения, паспорта, свидетельства о рождении, техпаспорта, доверенности |
| `[ДЕЛО1]` | номера дел (7527-24-00-2/1543, «дело №…», «іс №…») |
| `[ГОСНОМЕР1]` | госномера машин (рядом «г/н», «автомашина», «көлік»…) |
| `[СЧЕТ1]` | IBAN KZ…, расчётные счета, номера карт |
| `[ДР1]` | даты рождения («12.05.1990 г.р.», «1985 года рождения», «1990 жылы туған») |

Сохраняются статьи законов, суммы, даты событий, названия судов, госорганов и организаций.

**Качество.** На размеченном наборе из 9 фрагментов решений (ru и kk: потребители, алименты, КоАП, трудовой,
жилищный, кредит, АППК; 63 персональных значения) recall = 100 %, лишнего не замаскировано. На реальном
бюллетене ВС за 2025 год (80 страниц) ложные срабатывания единичны: названия стран после ролей. Акты в
бюллетенях уже обезличены до инициалов. Набор и замер — в `tests/test_zann_anonymize.py`. Его стоит
расширять на реальных актах, когда они появятся.

**Выгрузка** (единственная форма, в которой тексты покидают сервер):

```
python -m konsilier.cli zann-court-export OUT.jsonl [--source np,review,bulletin,acts] [--category labour,consumer] [--limit N]
```

В выгрузке есть id, источник, суд, категория, дата, язык, обезличенные название и текст, а также число
замен по видам. Для актов (`acts`) url и номер дела не выгружаются: по ним можно найти людей.

**Импорт актов**, полученных законно:

```
python -m konsilier.cli zann-court-import DIR [--category labour] [--court "Сарыаркинский районный суд г. Астаны"]
```

Файлы .pdf, .docx, .rtf, .txt, .html; рядом можно положить `<файл>.json` с полями
court/category/date/number/title/url.

## 6. Как включить (настройки сервера, по умолчанию выключено)

```
ZANN_COURT_ENABLED=true          # включить задачу
ZANN_COURT_HOUR=4                # ночной прогон в 4:00 по Алматы (4:00–4:50); -1 = непрерывно
ZANN_COURT_MINUTES=50            # длина одного прогона
ZANN_COURT_PAUSE=1.0             # пауза между запросами, c (≥ 0,5; Crawl-delay sud.kz 10 c действует поверх)
ZANN_COURT_SOURCES=               # пусто = все источники пакета (np,review,bulletin)
ZANN_COURT_REFRESH_DAYS=30       # повторный обход страниц (новые документы)
ZANN_COURT_MAX_MB=60             # файлы больше — пропускаются
```

Страна — `ZANN_COURT_COUNTRY` (пусто: единственный пакет с `zann/court.yaml`, сейчас kz); источники по
умолчанию — все из пакета. Перед включением применить миграцию `alembic upgrade head` (таблицы `zann_court_pages`, `zann_court_docs`).
Ручной запуск: `python -m konsilier.cli zann-court --discover` (только обход страниц), затем
`python -m konsilier.cli zann-court --minutes 60`.
